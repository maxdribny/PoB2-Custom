# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Path of Building 2 (PoBC) — an offline build planner for Path of Exile 2, written in **Lua (LuaJIT 5.1)**. It runs on a custom 2D graphics host called **SimpleGraphic** (shipped as a compiled binary in `runtime/`). There is no compile step for the Lua source: the program runs directly from the repo.

This is a **standalone copy** of [PathOfBuildingCommunity/PathOfBuilding-PoE2](https://github.com/PathOfBuildingCommunity/PathOfBuilding-PoE2) — **not** a GitHub fork. See "Branches & upstream sync" below before committing anything.

## Branches & upstream sync

- `custom` — your custom work lives here (this is the working/default branch).
- `dev` — kept as a **clean mirror** of the official upstream `dev`. **Never commit to `dev` directly.** Upstream PRs are staged on `dev` then merged to `master`; here `dev` is read-only mirror.
- Per the global rule, check out a new branch off `custom` for new features.
- To pull in upstream changes, run `./sync/Sync-Upstream.ps1` (PowerShell) or `bash sync/sync-upstream.sh`. It fast-forwards `dev` to `upstream/dev`, then merges `dev` into `custom`. Use `-NoPush` / `--no-push` to preview. See `sync/README.md`.

## Running the app

Run the bundled executable directly from the repo — running this way auto-enables **Dev Mode** (disables auto-updates, sets user path to script path):

```
./runtime/"Path of Building-PoE2.exe"
```

Dev Mode debugging features (from `CONTRIBUTING.md`):
- `F5` restarts the program in-place.
- `Ctrl`+`~` toggles the console (US keyboard layout is safest). `ConPrintf()` prints to it.
- Hold `Alt` over items/passives/tooltips to see internal modifiers and unrecognised stat parts; in the Tree tab it highlights nodes with unrecognised mods.
- Hold `Ctrl` while launching to rebuild the mod cache.

## Tests

Tests use the [Busted](https://lunarmodules.github.io/busted/) framework and live in `spec/System/` (files named `Test*_spec.lua`). Config is in `.busted`; tests run headlessly against `src/` via `src/HeadlessWrapper.lua` (which stubs the SimpleGraphic host).

Run the full suite via Docker (no local Lua toolchain needed):

```
docker-compose up
```

To run locally with a Lua toolchain installed (LuaJIT + busted), from `src/`:

```
busted --lua=luajit
```

On Windows/PowerShell with Busted installed via LuaRocks, the external LuaJIT process may not find the bundled runtime C modules by default. From the repo root, prepend `runtime\?.dll` to `LUA_CPATH` and let `.busted` load `src/HeadlessWrapper.lua`:

```
$env:LUA_CPATH="$PWD\runtime\?.dll;$env:LUA_CPATH"
busted --config-file=.busted --run=default --lua=luajit
```

Run a single spec or filter:

```
busted --config-file=.busted --run=default --lua=luajit "../spec/System/TestSkills_spec.lua"
busted --config-file=.busted --run=default --lua=luajit --filter="<pattern>"
```

The `.busted` config changes the working directory to `src`, so explicit single-spec paths are relative to `src` even when the command is launched from the repo root.

The `builds` tag is excluded by default (`exclude-tags` in `.busted`).

LuaJIT is expected to be installed on this Windows machine. Do not skip LuaJIT checks because `runtime\luajit.exe` is absent; use the installed `luajit.exe` on `PATH`, for example:

```
luajit -b src\Classes\TradeQuery.lua NUL
```

Full-suite Busted and LuaJIT commands can take time. Use a long timeout and let them finish. If an agent shell command prints the expected output but still reports a timeout, diagnose the shell invocation before treating the command as failed. In Codex on Windows/PowerShell, run `shell_command` with `login=false` when commands hang after output; this avoids the timeout behavior seen with login-shell invocation.

## Generated data — do not hand-edit

Large parts of `src/Data/` are **automatically generated** from Path of Exile GGPK game data and must not be edited by hand. Generated files carry the header `-- This file is automatically generated, do not edit!`. To change them, edit the corresponding scripts in `src/Export/` and re-run the exporter (the `.dat` viewer at `src/Export/Launch.lua`; see `CONTRIBUTING.md` for the full GGPK/Oodle setup). Include both the script and regenerated data changes together.

`src/Data/ModCache.lua` is special: it is a very large file regenerated from the `ModParser`. If you change mod-parsing logic, reload PoB with `Ctrl`+`F5` to regenerate it, and **commit `ModCache.lua` if it changes** — diffing it is how unintended mod-parsing side effects are caught.

## Architecture

The program has two top-level modes, both driven from `src/Modules/Main.lua`: the **build list** (`BuildList.lua`) and an open **build** (`Build.lua`). Entry is `src/Launch.lua` (the `#@ SimpleGraphic` shebang tells the host which script to run), which loads `Modules/Main` inside a protected environment and wires up frame/key/update callbacks.

Key layers:

- **`src/Launch.lua`** — program entry point, dev-mode detection, manifest/version loading, update orchestration, error prompts. `src/LaunchServer.lua` and `src/HeadlessWrapper.lua` are alternative hosts (server / headless-for-tests).
- **`src/Modules/`** — the engine and top-level screens:
  - `Main.lua` loads everything (game version, `Common`, `Data`, the various `*Tools`), manages modes, mod caches, and trees.
  - `Build.lua` — the build screen: orchestrates all tabs, builds the calculation output and sidebar stat list, save/load, version migration.
  - **Calc pipeline** (`Calcs.lua` loads the rest): `CalcSetup.lua` assembles the per-actor mod databases (player + enemy) from tree nodes, items, jewels (incl. radius/timeless), flasks, bandits, pantheons, granted skills — building the calculation environment. `CalcPerform.lua`, `CalcOffence.lua`, `CalcDefence.lua`, `CalcActiveSkill.lua`, `CalcTriggers.lua`, `CalcMirages.lua` then compute results. `CalcBreakdown.lua` / `CalcSections.lua` / `CalcFormat.lua` produce the Calcs-tab breakdown UI. `CalcTools.lua` holds shared mod-value/gem helpers. See `docs/calcOffence.md`.
  - **Mod system**: `ModParser.lua` parses mod text (items, skills, pantheon) into structured mods → produces `ModCache`. `ModTools.lua` creates/formats mods and loads the cache. The runtime mod database classes are `ModDB.lua`, `ModList.lua`, `ModStore.lua` (in `src/Classes/`). See `docs/addingMods.md` and `docs/modSyntax.md`.
  - `Data.lua` loads all static/generated game data (uniques, bases, gems, skills, stat descriptions, mods, essences, etc.). `Common.lua` is the utility belt (class system, encoders, MurmurHash, JSON, table helpers).
- **`src/Classes/`** (~79 files) — UI controls and per-tab logic. Tabs: `CalcsTab`, `ConfigTab`, `ItemsTab`, `SkillsTab`, `TreeTab`, `ImportTab`, `NotesTab`. Domain objects: `Item.lua`, `PassiveSpec.lua` (allocated tree state), `PassiveTree.lua` / `PassiveTreeView.lua` (tree data + rendering). The rest are generic widgets (`Control`, `ButtonControl`, `DropDownControl`, `EditControl`, `ListControl`, `Tooltip`, …). PoB uses its own class library from `Common.lua`, not OO Lua libraries.
- **`src/Data/`** — generated + curated game data. `Global.lua` holds enums/flags reverse-engineered from the GGPK. `New.lua` is where newly-announced uniques live until mod ranges are known.
- **`src/Export/`** — the GGPK exporter scripts that generate `src/Data/`. Has its own `Launch.lua`/`Main.lua` (the "Dat View" tool). Requires Oodle binaries in `src/Export/ggpk/`.
- **`src/TreeData/`** — passive tree data per version. Game/tree versions are defined in `src/GameVersions.lua` (`treeVersionList`, `liveTargetVersion`).

## Conventions

- `.editorconfig` governs formatting. Lua source in this project uses **tabs** for indentation — match the surrounding file.
- EmmyLua-style annotations (`---@type`, `---@param`) are used; EmmyLua is the recommended editor tooling (see `CONTRIBUTING.md` for VS Code / JetBrains debugger setup over port 9966).
- Changelog lives in both `CHANGELOG.md` (Markdown) and `changelog.txt` (plain text, consumed by the updater).
- `manifest.xml` maps filename→SHA-1 for the updater; `update_manifest.py` regenerates the hashes (new files must be added manually).
- **Commits**: never sign commits with text suggesting they were generated by Claude or any other AI assistant (no `Co-Authored-By` / "Generated with" trailers).
