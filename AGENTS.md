# Repository Guidelines

## Project Structure & Module Organization

This repository is a standalone custom copy of Path of Building 2. Custom work belongs on the `custom` branch; `dev` is kept as a clean mirror of upstream. Core Lua application code is in `src/`, with generated game data under `src/Data` and exporter scripts under `src/Export`. Tests live in `spec/System` and use Busted. Documentation is in `docs/`, upstream sync tooling is in `sync/`, and the packaged runtime plus Lua dependencies are in `runtime/`. Local logs are written to `logs/`.

## Build, Test, and Development Commands

- `./run.bat`: launch the app from the repository root on Windows.
- `./runtime/PathofBuilding-PoE2.exe`: run the development installation directly.
- `busted --lua=luajit "../spec/System/<name>_spec.lua"` from `src/`: run one Busted spec with the repository runtime path from `.busted`.
- `cd src; luajit HeadlessWrapper.lua`: run the headless wrapper; set `REGENERATE_MOD_CACHE=1` when regenerating `src/Data/ModCache.lua`.
- `./sync/Sync-Upstream.ps1` or `bash sync/sync-upstream.sh`: fast-forward `dev` from upstream, merge it into `custom`, and optionally push.

## Coding Style & Naming Conventions

Lua files use tabs for indentation and a 120-column target from `.editorconfig`. Preserve existing module patterns and names; many files use PascalCase module files and camelCase locals/functions. Avoid trimming trailing whitespace in Lua files because the editor configuration explicitly disables that cleanup. Do not hand-edit files marked `-- This file is automatically generated, do not edit!`; update exporter scripts instead.

## Testing Guidelines

Add or update specs in `spec/System`, using the existing `*_spec.lua` naming convention. Run the narrow spec first, then broader Busted coverage when changing shared calculation, parsing, or data behavior. When running Busted locally from PowerShell with LuaRocks-installed `busted`, include the bundled runtime DLLs on `LUA_CPATH` so modules such as `lua-utf8` load correctly. From the repo root, use:

```
$env:LUA_CPATH="$PWD\runtime\?.dll;$env:LUA_CPATH"
busted --config-file=.busted --run=default --lua=luajit "../spec/System/<name>_spec.lua"
```

Run the full default suite from the repo root with:

```
$env:LUA_CPATH="$PWD\runtime\?.dll;$env:LUA_CPATH"
busted --config-file=.busted --run=default --lua=luajit
```

LuaJIT is expected to be installed on this machine. For syntax-only checks, use:

```
luajit -b src\Classes\TradeQuery.lua NUL
```

The `.busted` config changes the working directory to `src`, so single-spec paths use `../spec/...`. Full-suite and LuaJIT commands may take time; use a long timeout rather than skipping them. If a command prints the expected output but the agent tool reports a timeout, diagnose the shell invocation before treating the command as failed. In Codex on Windows/PowerShell, prefer `login=false` for `shell_command` calls when commands otherwise hang after producing output. For modifier parsing changes, reload PoB with `Ctrl` + `F5` or run the headless cache regeneration and commit `src/Data/ModCache.lua` if it changes.

## Commit & Pull Request Guidelines

Recent local history uses concise subjects such as `feat: add Copy Results button...`, `Fix minion crit chance`, and merge commits into `custom`. Keep commits focused and descriptive. PRs should explain the problem, list verification steps, link an issue or build when relevant, and include before/after screenshots for UI-visible changes. Upstream-facing PRs target `dev`; custom-only work stays on `custom`.

## Agent-Specific Instructions

Respect the custom/upstream split. Never commit directly to `dev`, and avoid unrelated churn in generated data, runtime assets, changelogs, or logs unless the task specifically requires it.
